# 05 Netflix casting and app sources: findings

Research for [issue 05](../decisions/05-netflix-and-app-sources.md). Done 2026-10-19 from web sources only. Nothing was downloaded, installed or run. Each claim has a confidence mark and a source. "Snippet" means the page refused fetching and the fact comes from search-engine snippets of it.

## Answer in short

- **Casting:** yes. In Italy the Netflix iPad app can still cast to an old Chromecast without a remote. There are four limits: you need the Standard or Premium plan (not *Standard con pubblicità*), the iPad and the Chromecast must be on the same Wi-Fi, picture tops out at 1080p (4K only on a Chromecast Ultra with Premium), and live events don't play. Netflix already removed casting from most other devices without warning in Nov 2025, so this path may not last.
- **APK source:** Netflix, Disney+ and Prime Video don't offer an APK outside app stores. The best practical source is APKMirror. It checks every upload's signing certificate against earlier versions before it publishes, and it doesn't modify files. Pick single-APK `arm-v7a` (or universal) variants where they exist.
- **Check on Windows:** run `apksigner verify --verbose --print-certs` (from Google's Android SDK Build-Tools) on every APK. Compare the certificate SHA-256 with the value on the APKMirror page and with an older version of the same app, then write it down. After the first install, Android itself refuses any update signed with a different key.

## 3. Checking an APK's authenticity on Windows

**Tools (official):** Google's Android SDK Build-Tools include `apksigner` (from 24.0.3) and `aapt2` (from 26.0.2). Install them with Android Studio's SDK Manager, or with the command-line tools and `sdkmanager "build-tools;36.0.0"`. Google now marks `sdkmanager` as deprecated in favour of `android sdk`. You need a Java runtime. Google's guidance found no official minimum. CI setups pair it with JDK 17 (open-source Eclipse Temurin), so use that (low-medium). WSL Ubuntu 20.04 only has the old `apksigner` 0.9 package, so use the Windows build-tools instead (medium). Sources: https://developer.android.com/tools/apksigner, https://developer.android.com/tools/aapt2, https://developer.android.com/tools/sdkmanager, https://manpages.ubuntu.com/manpages/focal/man1/apksigner.1.html, https://gitea.com/actions/setup-android

**Steps, for every APK file (each split too):**

1. **Signature valid:** run `apksigner verify --verbose --print-certs file.apk`. Pass means no error, `true` for the v2 and/or v3 scheme ("Verified using v2 scheme" lines; `--verbose` shows them), and exactly one signer. Note the line `Signer #1 certificate SHA-256 digest: <64 hex>`. Sources: https://developer.android.com/tools/apksigner; the digest line format from https://ente.com/help/photos/getting-started/android-apk-signature (high); the scheme lines from a snippet of https://discuss.grapheneos.org/d/14675-best-practice-for-installing-obtainium-from-github (medium).
2. **Right publisher:** compare that digest with three things: (a) the certificate SHA-256 on the APKMirror page for that exact version, (b) the digest of an older version of the same app, ideally a year or more older, and (c) if you run apkeep once, the copy from Google Play. apksigner prints lowercase hex without colons, while websites often show uppercase with colons, so normalise both before comparing (high, https://ente.com/help/photos/getting-started/android-apk-signature). Any mismatch means stop. One exception: APKMirror says apps can legitimately rotate keys (APK Signature Scheme v3). If the digest changes, it has to come with a v3 lineage. Source: https://www.apkmirror.com/faq/ (snippet).
3. **Pin it:** write each app's digest into the project files (the runbook decides where). Every later update is checked against that pinned value. Android does the same on the device: "The system allows the update if the certificates match." So the first install is the one that has to be right. Source: https://developer.android.com/studio/publish/app-signing (high).
4. **Right app and architecture:** run `aapt2 dump badging file.apk`. The package name must be exactly `com.netflix.mediaclient`, `com.disney.disneyplus` or `com.amazon.avod.thirdpartyclient`, and the native code must include `armeabi-v7a`. Google documents only that badging "prints information extracted from the APK's manifest", so the exact field names are from experience (medium). Source: https://developer.android.com/tools/aapt2
5. **Download not corrupted:** run `Get-FileHash file.apk -Algorithm SHA256` and compare with the SHA-256 file hash on the APKMirror page. This is a weaker check than step 2 and only proves the transfer. Source: https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash
6. **Bundles:** every split must give the same certificate digest. Install them together with `adb install-multiple base.apk split_config.armeabi_v7a.apk ...`. Android rejects splits signed with different certificates (AOSP test, medium). Source: https://android.googlesource.com/platform/cts/+/6302bb5%5E%21/

**What passing proves, and what it doesn't:** it proves the file was signed with the publisher's key (or Google Play's signing key for that app) and hasn't been changed since. It says nothing about how the app behaves. A stolen publisher key, as in the SmartTube case, would also pass. That remaining risk is covered by the 24-hour guest-network re-check after every new app.

## Can only be confirmed on the unit (or the stick)

- Which Chromecast it is: 1st, 2nd or 3rd gen, or Ultra. Read the label on the stick, or look in Google Home on the iPad without changing anything. If it's 2nd gen, also confirm it has received the post-March-2025 firmware, which in practice means it still casts today.
- That the Cast icon appears in Netflix on the iPad. That depends on the account plan being Standard or Premium and on the iPad's Local Network permission for Netflix.
- That Netflix plays through the Chromecast on the HY320's HDMI input without "HDCP Unauthorized", and the projector's native panel resolution.
- Whether the HY320 firmware declares `android.software.leanback`, which decides whether the Android TV builds (Disney+, Prime Video) install or only the phone builds. Read-only check: `adb shell pm list features`.
- The ABI list (`getprop ro.product.cpu.abilist`), which confirms that only armeabi-v7a builds will run.
- Whether the stock firmware already ships Netflix, Disney+ or Prime Video. If it does, compare their certificates with the pinned values. A mismatch means the vendor modified them, and they go.
